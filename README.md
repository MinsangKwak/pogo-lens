# PoGo Lens

**내가 가진 포켓몬의 개체값을 비교하고, 보유 순위로 이름을 제안하는 Android 오버레이 앱을 개발하고 있습니다.**

포켓몬 GO와 앱을 번갈아 열며 개체값을 확인하고 이름을 바꾸는 반복 작업을 줄이는 것이 목표입니다. Kotlin은 화면 캡처와 오버레이를, TypeScript는 계산과 이름 규칙을 담당합니다.

> 개발 초기 단계입니다. 현재 Android는 플로팅 버튼으로 화면 한 장을 받아 크기를 표시합니다. OCR, 보유 목록 저장, 게임 안 이름 입력은 아직 연결되지 않았습니다.

## 우선 해결할 문제

1. 상세·평가 화면에서 읽은 값을 사용자가 확인합니다.
2. 확정한 포켓몬을 같은 종·폼끼리 비교합니다.
3. 보유 순위와 개체값이 담긴 12자 이내 이름을 제안합니다.
4. 사용자가 확인한 이름을 복사하거나 키보드로 입력합니다. 마지막 두 단계의 Android UI는 구현 예정입니다.

예: 같은 종을 2마리 등록했을 때 `1/2 FFF`, `2/2 AFF`를 제안합니다. `FFF`는 공격·방어·체력 15/15/15를 16진수로 압축한 표기입니다. 새 개체를 추가하면 기존 개체의 제안 이름도 다시 계산합니다.

## 현재 구현 범위

| 영역 | 구현한 내용 | 남은 작업 |
| --- | --- | --- |
| 계산 코어 | CP·HP, IV 후보 역산, 리그별 4096 IV 조합 비교 | 실제 종 데이터와 갱신 체계 |
| 보유 순위·이름 | 종·폼별 순위, 닉네임 템플릿, 순위와 이름 제안 통합 | 중복 스캔 식별, 저장과 이름 변경 이력 |
| Android | 권한·캡처 동의, 플로팅 버튼, 한 프레임 캡처, 알림 중지 | OCR, 결과 카드, TypeScript 호출 연결 |
| 디자인 | 한국어 설정 화면, 반투명 청록 패널과 작은 유리 느낌 버튼 | 기기에서 화면·큰 글자·TalkBack 검증 |

보유 순위는 **IV 합 → 공격 → 방어 → 체력** 순서입니다. 세 IV가 모두 같은 개체는 공동 순위이며 이후 순위는 건너뜁니다. 이는 레이드 실전 성능 순위가 아닙니다. PvP 순위도 기술·상성 기반 종 티어가 아니라 같은 종의 스탯 곱 순위입니다. 기본 최대 레벨은 51이므로 베스트 파트너를 제외하려면 `maxLevel: 50`을 지정합니다.

## 설계에서 신경 쓴 부분

- **화면과 계산 분리:** 순수 TypeScript 함수를 테스트할 수 있도록 Android API를 코어에서 분리했습니다. 실제 호출 방식은 아직 결정하지 않았습니다.
- **잘못된 인식값 차단:** IV 범위, 레벨 간격, CP·HP, 미지원 강화 비용을 검사합니다. 모르는 모래 비용을 모든 레벨 검색으로 조용히 바꾸지 않습니다.
- **예측 가능한 이름:** 여러 `{name}` 토큰도 같은 글자 예산을 나눠 쓰고, 전체 길이를 유니코드 코드 포인트 기준 12자로 제한합니다. 게임의 실제 입력 허용 문자는 기기에서 검증해야 합니다.
- **캡처 수명 관리:** 중복 요청 방지, 3초 제한, 종료 시 대기 요청과 이미지 자원 정리를 적용했습니다.
- **작은 권한 범위:** 현재 인터넷·외부 저장소·접근성 서비스 권한이 없으며 캡처 이미지를 파일로 저장하지 않습니다.

## 실행과 검증

Node.js `22.12+`의 22 계열, 24 계열 또는 26 이상을 사용합니다.

```bash
npm ci
npm run check
```

`check`는 ESLint, TypeScript 타입 검사, Vitest, 코어 빌드를 실행합니다. 의존성 점검은 `npm audit`로 별도 수행합니다.

Android Studio에서 `apps/android/`를 열고 JDK 17, Android SDK 35를 준비합니다.

```bash
cd apps/android
./gradlew assembleDebug lintDebug
```

실제 게임 위에서의 검증 절차와 알려진 제약은 [보안·검증 기록](docs/SECURITY_REVIEW.md)에 정리했습니다. 빌드 성공과 실제 게임 동작 검증은 구분합니다.
