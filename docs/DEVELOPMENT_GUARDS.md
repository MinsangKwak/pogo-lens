# 데이터와 동작 계약

RN UI·네이티브 캡처·공유 코어를 확장할 때 유지할 계약입니다. 타입 선언만으로 끝내지 않고 경계 검증과 실패 상태를 함께 다룹니다.

## 확인·저장

- `ScanCandidate`는 미확인·휘발성 상태입니다. OCR 원문과 캡처 결과를 확인 전 보유 수·순위·영구 컬렉션에 넣지 않습니다.
- `CollectionState.schemaVersion = 1`입니다. 최신 개체(`records`), 확인 관측(`observations`), 이름 적용 이력(`nicknameApplications`)을 분리합니다.
- 개체 ID와 관측 ID는 앱 내부 식별자입니다. 게임의 고유 ID로 해석하지 않습니다. 동일 종·IV만으로 자동 병합하지 않고 `new` 또는 `update`와 대상 ID를 명시합니다.
- IV는 각각 0~15 정수입니다. CP·HP·레벨을 읽지 못하면 생략하며 0으로 채우지 않습니다. 재확인은 제공한 필드만 갱신하고 기존 이름·보호를 보존합니다. 종·폼이 다른 개체나 오래된 관측으로 현재 기록을 덮어쓰지 않습니다.
- 네이티브는 AsyncStorage 3에 확인 완료 컬렉션만 저장합니다. 웹은 현재 탭 메모리이며 새로고침 시 초기화합니다. 양쪽 모두 같은 직렬화 검증을 사용합니다.
- 초기 로드 실패·미지원 스키마·손상 데이터에서는 원본을 보존하고 저장을 차단합니다. 빈 컬렉션으로 조용히 덮어쓰지 않습니다. 원본 내보내기와 명시적 전체 삭제를 제공합니다.
- 저장이 성공한 뒤 UI의 확인 상태를 반영합니다. 중복 저장을 차단하고 실패 시 이전 기록과 작성 후보를 유지합니다. 초기 로드와 네이티브 후보 응답의 도착 순서가 달라도 이미 확인한 관측을 다시 노출하지 않아야 합니다.
- 직렬화 경계는 목록 개수·JSON 크기·ID 중복·이력 참조·스키마·값 범위를 검사합니다. 지원하지 않는 미래 형식을 추정해 읽지 않습니다.

## 순위·이름

- `owned-iv-v1`은 같은 종·폼의 **IV 합 → 공격 → 방어 → 체력**, 동일 IV 공동 순위입니다. PvP·레이드 순위와 혼합하지 않습니다. 데이터는 현재 `fixture-v1`의 4종 샘플입니다.
- 제안 스냅샷에는 보유 목록·현재 이름·보호 상태·템플릿·종 데이터·정책 버전을 포함합니다. 복사·적용 직전 달라졌다면 새 제안을 검토합니다. 스냅샷은 인증 서명이 아닙니다.
- 이름은 1~12 유니코드 코드 포인트입니다. 공백만 있는 이름·제어 문자·보이지 않는 포맷 문자를 거부합니다. 실제 게임의 허용 문자·글자 수 해석은 별도 기기 검증 대상입니다.
- 제안은 현재 이름을 바꾸지 않습니다. 복사도 적용 이력을 만들지 않습니다. 네이티브에서 사용자가 게임 수동 적용을 확인해야 `user-confirmed`로 기록합니다. 게임 상태를 자동으로 검증했다는 뜻은 아닙니다.
- 웹 입력 연습은 `web-simulation`이며 게임 적용으로 취급하지 않습니다. UI·내보내기·이력에서 출처를 유지합니다.
- `nicknameLocked`는 명시적으로 해제하기 전까지 복사·적용을 막습니다. 직접 고친 이름은 적용 후 보호를 기본 권장하고 사용자 선택을 기록에 반영합니다. 다른 개체의 순위 변화도 변경 대기 제안으로 남깁니다.

## 네이티브 캡처

- `NativePogoLensCapture.ts`의 Codegen TurboModule 명세를 양 플랫폼이 구현합니다. JSON `protocolVersion = 1`을 확인하고 응답 크기·필드·개수를 제한합니다. 원본 이미지를 JS 응답에 넣지 않습니다.
- Android는 현재 프레임 시각·크기만 전달합니다. OCR·IV 자동 인식을 완료한 것처럼 UI나 문서에 표시하지 않습니다.
- iOS는 ReplayKit과 iOS 27 ScreenCaptureKit 경로를 버전·SDK 조건으로 나눕니다. App Group 미설정·지원 SDK 부재·시뮬레이터는 캡처 불가 상태와 안내를 반환합니다.
- iOS는 사용자 시작 세션에서 최대 1fps·10분으로 제한합니다. Vision의 평가 화면 후보를 최소 CP·HP·평가 라벨 텍스트로 줄입니다. 종·IV는 수동 확인하며 원본 이미지·영상·음성 파일을 만들지 않습니다.
- iOS App Group 후보는 최대 12개·10분 유효기간과 파일 크기 제한을 둡니다. 만료된 후보를 반환하지 않는 것과 파일을 물리 삭제하는 것은 구분합니다. 초기화 시 대기 결과를 지웁니다.
- 연속 프레임 중복 억제는 세션별 메모리 픽셀 지문을 사용합니다. CP·HP 텍스트가 같다는 이유만으로 다른 IV 화면을 버리거나 개체를 병합하지 않습니다. 지문·이미지는 영구 저장하지 않습니다.
- 중지·일시 중지·만료·취소 후 도착한 작업을 채택하지 않습니다. 오래된 세션의 결과가 새 세션에 쓰이지 않아야 합니다. Android 회전·영역 변경과 iOS 공유 대상 변경은 수명 정책에 따라 중지합니다.
- 시스템 동의·보호 화면을 우회하지 않습니다. 게임 화면 식별·인식 정확도·발열·메모리는 실제 기기에서 검증해야 합니다.

| 기능                         | 선행 조건                                                                 |
| ---------------------------- | ------------------------------------------------------------------------- |
| 전체 도감·폼·PvP UI          | 출처·라이선스·버전, 업데이트 전후 회귀, 리그·레벨 상한 표시               |
| Android OCR·IV 바 인식       | 실제 화면 fixture와 정답, 읽지 못한 필드의 빈 상태, 보정·확인 흐름        |

## 검증 명령과 완료 기준

```bash
npm ci
npm run check
npm run bundle:android
npm run bundle:ios
npm run typecheck:web -w @pogo-lens/mobile
npm run build:web -w @pogo-lens/mobile
```

`check`와 `build`는 네이티브 앱 빌드가 아닙니다. Android는 `apps/mobile/android`에서 `bash gradlew --no-daemon testDebugUnitTest lintDebug assembleDebug`, iOS는 CocoaPods 설치 후 호스트·Broadcast Extension의 Xcode 빌드를 별도로 실행합니다.

`.github/workflows/checks.yml`은 JS/TS·번들·웹·Android·iOS 작업을 정의합니다. 검사 정의나 이전 커밋의 성공을 최신 커밋 성공으로 간주하지 않습니다. 서명 없는 시뮬레이터 빌드는 App Group 프로비저닝·기기 캡처 검증을 대신하지 않습니다.

UI 이벤트 테스트는 IV 오류·명시적 중복 처리·복사와 적용 분리·보호·웹 입력 연습·삭제 확인을 검사합니다. 저장과 브리지는 별도 테스트로 검사합니다. 테스트 개수와 통과 여부는 실행 로그를 근거로 기록하고 실제 권한·캡처·접근성은 [기기 검증](SECURITY_REVIEW.md)을 완료합니다.
