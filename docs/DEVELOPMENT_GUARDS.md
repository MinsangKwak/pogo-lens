# 확장을 위한 데이터와 동작 계약

## 현재 코드로 강제하는 것

- `COLLECTION_SCHEMA_VERSION = 1`. 개체는 앱이 발급한 고정 ID로 관리한다. 게임의 고유 ID라고 해석하지 않는다. 웹은 UUID를 사용하고 모든 데이터는 탭 메모리에만 둔다.
- `ScanRecord`는 개체의 최신 확인값이다. `ScanObservation`은 관측 ID, 출처, 시간, 확인한 필드로 나누고 `confirmObservation`으로 사용자가 지정한 개체 ID에 연결한다. 동일 IV만으로 합치지 않는다.
- 읽지 못한 CP·HP·레벨은 생략한다. 업데이트는 제공한 필드만 적용하고 기존 값·닉네임·이름 보호를 보존한다. 종·폼 변경은 일반 재스캔 업데이트로 처리하지 않는다.
- `OWNED_RANK_POLICY_VERSION = owned-iv-v1`은 같은 종·폼의 IV 합 → 공격 → 방어 → 체력, 동일 IV 공동 순위다. PvP·레이드 순위와 혼합하지 않는다.
- 이름 제안에는 보유 목록, 기존 이름, 잠금 상태, 템플릿, 종 데이터 버전과 계산 정책 버전의 스냅샷을 붙인다. 실제 적용 직전에 다시 비교해 변동이 있으면 재확인을 요구한다. 스냅샷은 인증 서명이나 영구 개체 ID가 아니다.
- 다른 개체에 영향을 주는 이름 변경은 대기 제안으로 남긴다. `nicknameLocked`를 명시적으로 해제하기 전에는 적용하지 않는다. 적용 이력은 이전·새 이름, 시점, 기준과 출처를 별도 기록한다. 웹 예시는 반드시 `web-simulation`이며 게임 적용으로 취급하지 않는다.
- 이름은 1~12 코드 포인트로 제한하고 빈 이름·제어 문자·보이지 않는 포맷 문자를 거부한다. 실제 게임 문자 허용 규칙은 기기에서 별도 검증한다.
- PvP 캐시 배열·행·IV는 런타임에도 불변이다.
- 캡처 종료 시 작업을 취소하고 현재 캡처 소스와 다른 결과를 버린다. Android 14+의 최초 공유 크기는 수용하며 후속 크기 변경은 중지한다. 전 지원 버전에서 방향 변경 시 중지한다.

## 다음 기능을 연결하기 전 완료할 것

| 연결할 기능 | 선행 조건 |
| --- | --- |
| Android ↔ 계산 코어 | 실행 엔진 또는 Kotlin 이식 결정, 버전이 있는 JSON 입출력 계약, 동일 fixture 결과 비교, 예외·취소·시간 제한 검증. 지금 Android에서 TS 코어를 실행하는 것은 아니다. |
| 영구 저장 | 위 세 엔터티를 분리한 저장소와 트랜잭션, schemaVersion 검증, 이전 버전 마이그레이션·실패 복구 테스트, 내보내기·삭제. 미지원 버전을 조용히 덮어쓰지 않는다. |
| OCR | 한 프레임의 출처·규격·화면 종류 확인, 필드별 신뢰도와 미확정 상태, 수동 보정. 범위 0~15 통과만으로 자동 확정하지 않는다. 원본 이미지는 기본 저장·전송하지 않는다. |
| 전체 도감·PvP | 출처·라이선스·폼·데이터 버전 표시, 업데이트 전후 회귀 확인, 레벨 상한·리그 기준 명시. 현재 웹 데이터 버전은 `fixture-v1`, 4종 샘플이다. |
| 게임 이름 입력 | 사용자가 선택한 대상·현재 화면·제안 유효성을 적용 직전에 확인. 복사 성공과 게임 적용 성공을 구분하고 실제 적용 확인 전 이력을 완료 처리하지 않는다. |
| 교환 지원 | 보호 조건과 후보 수동 확인부터 설계. 좌표 자동 실행은 별도 검토하며 현재 구현하지 않는다. |

## 검증

- `npm ci && npm run check`: 코어 lint, TypeScript, 49개 테스트, 빌드.
- `apps/android`: `bash gradlew --no-daemon testDebugUnitTest lintDebug assembleDebug`. 순수 캡처 크기 정책 테스트 3개 포함.
- `.github/workflows/checks.yml`: PR·main 변경 시 두 작업 실행. GitHub Actions는 고정 commit, 권한은 contents 읽기만 사용한다. 필수 검사로 지정하는 branch protection은 저장소 관리자 설정이 필요하며 여기서 변경하지 않는다.
- 웹 별도 소스: 실제 코어 사본의 blob hash 검증, 원본 app.js 이벤트를 실행하는 워크플로 회귀 테스트, 브라우저 상호작용 확인.
- 실제 기기에서 권한 거절, 캡처 중지, 회전, 앱 단위 공유, 연타, 잠금, 백그라운드 복귀와 장시간 메모리를 확인한다. 단위 테스트·빌드는 이 검증을 대신하지 않는다.
