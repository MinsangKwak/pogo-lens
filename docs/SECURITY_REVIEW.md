# 보안·안정성 점검과 기기 검증

점검일: 2026-10-27. 대상은 초기 scaffold와 이번 보완 코드다. 소스 검토·코어 자동 검사·Android 리소스 컴파일을 수행했다. 기기 침투 테스트, 게임 계정 안전성 인증, 전체 공급망 감사는 아니다.

## 다루는 정보와 권한

| 항목 | 현재 상태 | 의도 |
| --- | --- | --- |
| 다른 앱 위에 표시 | 사용자가 설정에서 허용 | 작은 플로팅 버튼 표시 |
| 화면 캡처 | 세션마다 시스템 동의 | 탭할 때 프레임 한 장 읽기 |
| 포그라운드 서비스·알림 | 캡처 세션 중 사용 | 실행 상태 표시와 중지 |
| 인터넷 권한 | 없음 | 캡처·개체값 외부 전송 없음 |
| 외부 저장소·접근성 서비스 | 없음 | 전체 사진 접근·게임 입력 주입 없음 |
| 원본 이미지 파일·로그 저장 | 없음 | 메모리에서 처리 후 Bitmap 해제 |
| 보유 목록 DB·클립보드·IME | 미구현 | 추가 시 보관·삭제·입력 접근 범위 재검토 |

MediaProjection 세션은 사용자가 허용한 앱 또는 화면 영역을 계속 제공할 수 있다. 현재 코드는 탭할 때만 이미지를 읽지만 **포켓몬고 화면인지 자동 보장하지는 않는다.** 다른 앱으로 이동하기 전 알림의 중지 버튼을 사용해야 한다. 시스템의 보안 화면 차단이나 사용자 동의를 우회하지 않는다.

## 발견한 문제와 조치

| 우선도 | 문제 | 조치 |
| --- | --- | --- |
| 높음 | 캡처 연타로 ImageReader 리스너가 바뀌어 이전 요청이 대기할 수 있음 | 실행 중 요청 중복 차단, 3초 시간 제한 |
| 높음 | 시스템 캡처 종료 후 오버레이·대기 요청이 남을 수 있음 | 종료 콜백에서 자원 정리와 서비스 중지, 반복 해제 방어 |
| 높음 | 처리 예외·취소 시 이미지가 남을 수 있음 | Image.use, Bitmap finally·취소 해제 |
| 높음 | Android 10 지원 선언과 API 30 화면 크기 호출 불일치 | API 29에서는 DisplayMetrics 호환 경로 사용 |
| 보통 | 서비스 시작 예외가 사용자 화면에 반영되지 않음 | 실패 안내, 서비스 정리, StateFlow 상태 구독 |
| 보통 | 알림에서 빠르게 중지할 수 없음 | 명시적인 중지 액션 추가 |
| 보통 | IV 범위·레벨·인식 실패값으로 잘못된 이름 생성 가능 | 코어 진입 검증과 미지원 모래 비용 거부 |
| 보통 | 종 기본 스탯 변경 시 기존 PvP 캐시 재사용 | 기본 스탯을 키에 포함, 캐시 최대 8개 |
| 보통 | 개발 도구 취약점 3건 | Vitest 5.0.5로 업데이트, npm audit 재검사 0건 |
| 보통 | Android 12 이상 백업·기기 이전 규칙 미명시 | 백업과 기기 이전에서 앱 데이터 전부 제외 |
| 낮음 | 반복 이름 토큰이 뒤의 IV 표기를 잘라낼 수 있음 | 이름 토큰 개수별 글자 예산 분배 |
| 낮음 | 플로팅 버튼이 화면 밖으로 이동 가능 | 화면 범위 제한과 기기 터치 슬롭 사용 |

설정 화면의 캡처·권한 버튼에는 가림 터치 필터를 적용했다. MainActivity는 FLAG_SECURE로 자체 화면의 캡처를 제한한다. 이는 게임이나 다른 앱의 화면을 보호한다는 뜻이 아니며, 설정 화면 스크린샷이 차단되는 의도적인 동작이다.

## 자동 검사 기록

- `npm run check`: lint, typecheck, 테스트 31개, 코어 build 통과.
- `npm audit`: 알려진 취약점 0건. npm 개발 의존성까지 포함한 실행 시점 결과이며 Android 의존성 감사 결과가 아니다.
- Android XML 전체 파싱 및 SDK 35 `aapt2 compile`: 통과. 리소스 링크나 Kotlin 컴파일 성공을 의미하지 않는다.
- `designmd lint DESIGN.md`: 오류 0개. 정적 토큰 대비는 주요 버튼 10.72:1, 밝은 배경 쪽 본문 11.16:1, 보조 문장 7.35:1이다. 실제 기기의 투명 합성·TalkBack 검증을 대신하지 않는다.
- `assembleDebug lintDebug`: 저장소 지정 버전 Gradle 8.14.3, JDK 17, SDK 35에서 최종 변경분 통과. lint 오류 0개, 기존 런처 아이콘 관련 경고 2개가 남는다. Gradle 9 비호환 예정 API 경고도 있어 향후 AGP·Kotlin 업그레이드 때 재검증한다.

## 배포 전 실제 기기 확인

| 시나리오 | 기대 결과 |
| --- | --- |
| 최초 실행·권한 거절·재허용 | 권한 없는 상태가 표시되고 무단 캡처 없음 |
| 캡처 동의 취소·시작 버튼 연타 | 중복 세션 없이 다시 시작 가능 |
| 버튼 연타·3초 내 프레임 없음 | 요청 하나만 처리, 시간 초과 후 재시도 가능 |
| 시스템 캡처 중지·잠금·알림 중지 | 플로팅 버튼과 서비스 종료, 자원 해제 |
| 화면 회전·앱 단위 공유·다중 창 | 현재 제약 확인, 변경 후 중지·재시작 필요 |
| 화면이 보호되거나 검은 프레임 | OCR에서 성공 처리하지 않아야 함; OCR 연결 시 필수 |
| 설정 진입 중 다른 앱의 오버레이 | 권한·시작 버튼의 가림 터치 차단 확인 |
| 작은 화면·200% 글자·TalkBack | 내용이 잘리지 않고 버튼 접근 가능 |
| 30분 사용·반복 세션 | 메모리·발열·배터리와 서비스 종료 상태 확인 |

## 남은 위험과 다음 설계

- **강화 비용 조건:** 현재 모래 표는 일반 강화 비용 기준이다. 그림자·정화·이벤트 할인은 같은 비용이 다른 레벨을 뜻할 수 있어 OCR 연결 전 상태를 함께 입력받거나 비용 추론을 비활성화해야 한다.
- **오인식:** OCR이 생기면 확정 전 상태, 수동 보정, 종·폼·CP·HP 교차 검증이 필요하다.
- **중복과 오삭제:** 스캔 ID는 앱 기록 ID이며 게임의 고유 개체 ID가 아니다. 같은 수치만으로 다른 개체를 합치지 않는다.
- **교환 오작동:** 좌표 자동 입력은 정렬·스크롤·상대 상태 변화를 다루지 못한다. 이번 작업에서 구현하지 않았다.
- **미래 키보드:** IME는 민감한 입력을 볼 수 있으므로 별도 위협 모델과 개인정보 처리 원칙 없이는 추가하지 않는다.
- **화면 규격:** Android 14+ 최초 공유 크기를 반영하고 이후 크기 변경은 중지하며, 전 지원 버전에서 회전 시 중지한다. Android 10~13의 동일 방향 다중 창 크기 변경과 OCR 영역 맞춤은 별도 검증이 필요하다.
- **공급망:** Gradle 배포 ZIP의 공식 SHA-256을 확인해 wrapper 설정에 고정했다. AndroidX·Kotlin 의존성, 릴리스 서명·키 보관, 데이터 출처·라이선스는 배포 전 별도 점검한다.
