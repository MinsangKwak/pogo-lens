# 제품 우선순위와 확장 방향

1순위는 **내 보유 개체를 비교하고 이름을 제안하는 흐름**입니다. React Native 공통 UI·저장·계산은 연결했으며, 캡처와 게임 화면의 정확도·기기 동작을 검증한 뒤 지원 범위를 넓힙니다.

## 현재 도달한 범위

| 항목         | 현재 상태                                                                               |
| ------------ | --------------------------------------------------------------------------------------- |
| 공통 앱      | Android·iOS용 RN UI, 같은 컴포넌트의 웹 체험                                            |
| 값 확인      | 종·IV 수동 입력, 유효성 검사, 명시적 기존/새 개체 선택                                  |
| 비교·이름    | 실제 공유 코어 계산, 변경 대기 목록, 이름 보호와 적용 이력                              |
| 데이터       | 네이티브 확인 완료 기록 저장·내보내기·전체 삭제, 웹 메모리                              |
| Android 캡처 | 플로팅 버튼과 프레임 메타데이터. OCR·자동 수치 입력은 미구현                            |
| iOS 캡처     | ReplayKit / iOS 27 ScreenCaptureKit 코드와 Vision 최소 텍스트 후보. 실제 기기 검증 대기 |

자동 검사나 웹 체험 성공만으로 실기기 MVP 완료를 선언하지 않습니다. 현재 종 데이터는 개발용 4종이며 전체 포켓몬 지원 상태가 아닙니다.

| 우선순위 | 작업                              | 완료 조건                                                                   |

| P0       | 기기별 캡처 수명 검증             | 시작·거절·취소·중복 요청·잠금·중지·복귀·제한 시간 검증                      |

| P1       | 전체 종 데이터                    | 출처·라이선스·폼·데이터 버전, 오프라인 로딩과 갱신 회귀 검사                |
| P1       | 저장 운영 보완                    | 스키마 마이그레이션·복구, 큰 목록 성능, 백업·기기 이전 정책 검증            |
| P1       | 접근성과 실제 이름 입력           | 큰 글자·TalkBack·VoiceOver·키보드, 12자와 게임 허용 문자 검증               |

MVP 완료 기준은 사용자가 동의한 화면에서 후보를 얻고, 값을 확인·저장·비교한 뒤 이름을 직접 적용하고 그 사실을 기록하는 전체 흐름입니다. 앱이 게임 이름을 자동으로 변경할 필요는 없습니다.

## 확장 후보

1. **용도별 비교:** 현재 보유 IV 순위와 PvP 스탯 곱 순위를 별도로 보여 줍니다. 기술·상대가 필요한 레이드 실전 순위와 혼합하지 않습니다.
2. **검토 효율:** 이전 관측과 다른 값·낮은 신뢰도 필드부터 확인하고, 이미 확인한 캡처의 중복 표시를 줄입니다.
3. **개체 관리:** 보호·메모·태그·이름 변경 이력 검색을 더합니다. 순위가 바뀌어도 직접 정한 이름을 보존합니다.
4. **내보내기와 복구:** 이미지 없는 확인 수치·기준 버전을 내보내고, 향후 가져오기는 별도 검증·미리보기 후 적용합니다.

## 2순위: 교환 지원

왼쪽 위부터 교환 가능한 개체를 처리하는 아이디어는 별도 기능으로 남겨 둡니다. 먼저 즐겨찾기·보호 조건을 제외한 후보 목록과 수동 확인 흐름을 설계합니다. 교환 가능 여부는 게임이 결정하며 정렬·스크롤·네트워크·상대 상태가 바뀔 수 있습니다.

현재는 자동 탭·교환·접근성 서비스 입력을 구현하지 않습니다. 자동 조작 도입 여부는 최신 서비스·배포 정책과 잘못된 대상 선택의 복구 방법을 검토하는 별도 결정입니다.
