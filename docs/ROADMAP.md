# 제품 우선순위와 확장 방향

## 1순위: 보유 개체 비교와 이름 제안

MVP 완료 기준은 게임에서 평가 화면을 읽고, 사용자가 확인한 값을 저장한 뒤 보유 순위에 맞는 이름을 게임 입력란에 전달하는 전체 흐름이다. 코어 테스트만 통과한 상태를 MVP 완료로 보지 않는다.

| 순서 | 작업 | 완료 조건 |
| --- | --- | --- |
| 1 | 캡처 안정성·권한·중지 | Android 10·14·15 이상에서 시작, 거절, 종료, 재시작 확인 |
| 2 | 종 데이터·코어 호출 방식 확정 | 종·폼·데이터 버전 매칭과 오프라인 계산 |
| 3 | 평가 화면 인식 | 스크린샷 fixture로 IV 바·이름·CP·HP 검증, 미확정은 수동 보정 |
| 4 | 로컬 저장과 중복 확인 | 재스캔이 보유 수를 늘리지 않도록 동일 개체 확인; 불확실하면 사용자 선택 |
| 5 | 결과 카드·이름 미리보기 | 순위 기준·비교 범위·IV를 보여 주고 이름 변경 승인 |
| 6 | 사용자 입력 지원 | 클립보드 또는 전용 IME 검토, 실제 입력란에서 사용자 직접 적용 |

포켓몬에는 스크린샷에서 얻을 수 있는 안정적인 고유 ID가 없다. CP·IV·종이 같다는 이유만으로 합치면 서로 다른 개체가 삭제될 수 있으므로 중복 후보를 보여 주고 사용자가 확정한다. 이름에 순위가 있으면 새 스캔 시 기존 이름이 바뀔 수 있어 변경 대상 목록을 별도로 관리한다.

## 2순위: 교환 지원

사용자 아이디어는 왼쪽 위부터 교환 가능한 개체를 처리하는 것이다. 현재 자동 교환은 구현하지 않는다. 목록 갱신, 정렬 변경, 스크롤, 네트워크 대기, 상대방 상태에 따라 좌표만으로 대상을 보장할 수 없기 때문이다.

먼저 교환 후보 목록과 수동 확인 흐름을 만든다. 즐겨찾기·색이 다른 개체·전설 등 보호 조건은 사용자 설정으로 명시하고, 잘못 읽은 화면에서는 후보를 제안하지 않는다. 게임 내 교환 가능 여부와 상대 상태는 게임이 최종 결정한다. 자동 조작 도입 여부는 최신 서비스 정책, 배포 정책, 사용자 승인과 복구 불가능한 잘못된 교환 위험을 검토한 별도 결정으로 남긴다.

## 추천 확장 기능

1. **보호 목록:** 중요한 개체에 보관 표시를 하고 이름 변경·교환 후보에서 제외한다.
2. **용도별 순위:** IV 합과 슈퍼·하이퍼리그 스탯 곱을 구분한다. 레이드 실전 순위는 기술·종족값·상대를 포함하는 별도 기능이다.
3. **인식 신뢰도와 수동 보정:** 잘못 읽은 값을 그대로 저장하지 않고 확인 전 상태를 둔다.
4. **이름 변경 이력:** 이전 이름, 제안 이름, 실제 적용 여부를 분리한다. 되돌리기는 문자열 제안이며 게임 자동 복구는 아니다.
5. **오프라인 내보내기·삭제:** 원본 이미지 없이 확정 수치만 내보내고 전체 삭제를 제공한다.
6. **원본 저장 없는 오류 제보:** 데이터 버전·기기·오류 단계만 기본 수집하고 이미지는 사용자가 별도로 첨부한다.

## 아직 결정하지 않은 것

- TypeScript를 Android에서 실행할 엔진 또는 Kotlin 이식 여부
- 종 데이터 라이선스·출처·버전과 갱신 방식
- 온디바이스 OCR 모델과 언어별 이름 매칭
- IME 채택 여부와 입력 정보 처리 정책
- 데이터 저장 포맷·보관 기간·백업·마이그레이션
